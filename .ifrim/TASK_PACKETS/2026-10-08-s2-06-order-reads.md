## Contract comun

Rute aditive in router orders, inainte de /{order_id}:
- GET /api/orders/read/page: view=active|history|all (default active), status
  optional enum, restaurant_id/driver_id optionale, from_date/to_date ISO UTC
  (inclusive start/exclusive end), limit1..100(default25), cursor optional.
  Response: items(array of safe order fields), next_cursor(string|null),
  has_more(bool), limit(int), data_warnings(array of safe codes).
- GET /api/orders/read/detail/{order_id}: history_before optional nonnegative
  int, history_limit1..50(default25). Response: order(safe fields), history
  (newest first safe embedded canonical audit entries), next_history_before
  (int|null), history_has_more(bool), data_warnings(array safe codes).
- Request sends X-Expected-Actor-ID for account-switch comparison. Auth
  authoritative every call; restaurant only own restaurant, driver resolved
  from drivers.user_id with optional driver_id consistency, no missing==missing
  ownership. Role filters cannot expand scope. No credentials in cursor.
- Stable cursor uses normalized created_at descending, tie-breakers id + _id.
  Malformed/missing dates included deterministically, marked unavailable; no
  invented timestamps/status. Cursor validated and bound to filters/actor.
  Database and external reads bounded deadlines, safe503 on failure, no writes.
- Detail projects explicit fields, excludes internal ledger/raw secrets. Audit
  UI shows action, actor role/id, time, versions and approved scalar changes;
  no raw untrusted objects/HTML. Embedded trail is canonical, no audit_log merge
  or inferred missing events. History anchor uses index so new appends cannot
  duplicate/displace older pages. Invalid data should warn not crash.
- Legacy list/response and writer contracts retained. Paginated admin browser
  replaces visible OrdersTab list, not unbounded full fetch traversal. Existing
  fleet/map/analytics legacy consumers retained and limitations reported.

## Frontend

Admin orders active/history/all, status/restaurant/courier/date filters, next/
previous, finite read-only refresh; preserve filters after mutations. Use
existing design/UI components. Data always validated, stale responses fenced
on actor/token/query/reload/unmount. Loading/error/offline/empty explicit,
timeout15s; no hidden write retry/fallback. Eye opens fresh read detail with
prep versus delivery, source and history; existing correction callback stays
available only eligible admin and uses fresh order. New controls must fit390px.
