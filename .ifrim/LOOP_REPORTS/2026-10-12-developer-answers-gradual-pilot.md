# ProDelivery decizii de dezvoltare și pilot gradual

Catalin a răspuns la întrebările D1–D5 la 12 octombrie 2026. Numerotarea este cea a grilei pentru dezvoltator din chat, distinctă de întrebările pentru client.

| Punct | Răspuns și efect în plan |
| --- | --- |
| D1 API | Accesul nu este obținut și furnizorul nu este nominalizat. Clientul discută cu restaurantul pentru identificarea programului, contactului furnizorului, documentației și accesului autorizat de test. Conectorul specific depinde de acestea. Introducerea manuală și OCR-ul, după implementarea și verificarea proprie, pot susține operarea independent. |
| Pilot gradual | Prima cohortă planificată are 2–3 restaurante. Scopul este verificarea fluxurilor și remedierea problemelor înaintea extinderii. Aceasta actualizează dimensiunea începutului pilotului; nu reduce capacitatea țintă sau funcționalitățile contractate. Activarea se face după verificările și acordul de lansare aferente etapei. |
| D2 = D | Fluxul concret al importului API se stabilește după analiza datelor și posibilităților furnizorului. Confirmarea umană ori importul direct și statusurile trimise înapoi rămân de stabilit. |
| D3 = B | Pregătim variante de servicii și costuri pentru prezentarea către client, înainte de activare. Plafoanele și cheltuielile rămân de aprobat. |
| D4 = D | Conturile Apple Developer și Google Play trebuie pregătite pentru firma clientului. Conturile, buildul/testarea iOS și aprobarea magazinelor sunt dependențe distincte. |
| D5 | Catalin cere explicarea responsabilităților: propunerea politicii și soluția tehnică sunt pregătite de echipa de dezvoltare; nevoile operaționale și instrucțiunile pentru date sunt validate de firma clientului sau persoana desemnată. Nu a fost adoptată încă o politică ori vreo perioadă concretă. |

Pentru D5, echipa de dezvoltare propune ce date sunt necesare, accesul pe roluri, duratele de păstrare pe categorii, regulile de ștergere/arhivare, backupul, monitorizarea și restaurarea. Firma confirmă scopurile și nevoile activității sale. Verificarea juridică, dacă este necesară, se face cu persoana competentă desemnată de firmă. Rolurile și instrucțiunile se consemnează în contract și acordul de prelucrare, conform situației efective; nu sunt deduse doar din numele rolurilor aplicației.

Această împărțire urmează planul comercial v1.2, capitolul 19, și [ghidul EDPB pentru operatori și persoane împuternicite](https://www.edpb.europa.eu/sme/learn-the-basics/data-controller-or-data-processor_en). Propunerea nu reprezintă validare juridică sau certificare de conformitate.

Etapele 1 și 2 rămân deschise. Ordinea de lucru este 1 → 2 → 3. Cerințele financiare și de pauză încă neclarificate de client rămân în raportul `2026-10-12-client-operational-rules-third-set.md`. Acest checkpoint este documentar; acceptarea aplicației, testele fizice și activarea pilotului sunt verificate separat.
